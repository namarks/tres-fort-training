# Security and private reports

Report vulnerabilities and account-specific problems privately to
**nick@tresfort.app**. Include the affected version, a short description and
steps that reproduce the problem with synthetic data. Do not send passwords,
access tokens, signing keys, or a complete database export.

GitHub issues and pull requests are for information suitable for publication.
Do not put real users' names, email addresses, workouts, health measurements,
routes, screenshots, raw TestFlight feedback, or unredacted crash logs in them.
Do not assume a closed issue or an edited comment is private.

For ordinary app support, use **Profile → Help → Report a problem**, TestFlight
feedback, or the support email. The operator can reproduce the problem with a
test account and publish a separate issue. Keep original reports in private
support storage; a public issue should not link to the private attachment.

Test only your own local installation and synthetic accounts. Access to this
repository does not authorize probing production, accessing another member's
data, or using the project's provider, deployment, or Apple credentials.

If private material is accidentally posted, contact the operator privately
with its location. Do not copy the material into another issue. Credential
exposure requires revocation or rotation as well as removal; editing a comment
alone can leave its earlier revisions accessible.

This policy does not promise a response deadline or a bug bounty. When GitHub
private vulnerability reporting is enabled, that channel can also be used;
email remains available regardless of the repository's visibility.
